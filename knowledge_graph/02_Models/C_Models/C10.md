# C10 — Governance & Safety Layer

> **Status: draft-for-review** (KG sprint 1, 2026-10-23). Filled to the ML-KG-04 fields; not `specified` until the owner has reviewed it (MLM SPECS2 §12). Resolves MLM SPECS2 **LO-08** (unit of RD_min, SG-C10-1) and SG-C10-2, SG-C10-3 (mlm-library SPEC_GAPS.md; library D-16, D-17); records the ML-RD-02 reconciliation with FLEXUS G-1..G-7. Items marked **OWNER DECISION** are proposals; see REVIEW.md.

## Purpose
Decides, for every proposed control action from the C-series ([[C01]], [[C05]], [[C06]]), whether it is allowed in full, derated or blocked, using the action's Response Derivative from [[C08]], safety flags and deterministic checks, and limits how fast the governed output may change. No control signal reaches an actuator without passing C10 (RD lifecycle step 6, governance).

## Layer
**RL/Q-Learning** — rule-based governance in the decision layer. Deterministic: a pure function of its inputs and parameters.

---

## Formula

### LaTeX
**Normalised RD** (LO-08, SG-C10-1):
$$\widetilde{RD} = RD \cdot \frac{\sigma_x}{P_{ref}}$$
where $RD$ is in W per unit of stimulus $x$ (units of `registers/rd_stimuli.csv`), $\sigma_x$ is the standard deviation of the stimulus over the trailing 30 days in the action's scope (same units as $x$), and $P_{ref}$ is the rated power of the asset or scope that delivers the response (W). $\widetilde{RD}$ is dimensionless: the change in flexibility, as a fraction of rated power, for a one-standard-deviation move of the stimulus.

**Governance** (SG-C10-3 completes the cases):
$$u_{governed} = \begin{cases} 0 & \text{if } storm \lor override \lor \lnot safety\_ok \lor RD \text{ invalidated or missing} \lor \widetilde{RD} \le 0 \quad (\text{block}) \\ \alpha_{derate}\, u_{proposed} & \text{if } 0 < \widetilde{RD} < RD_{min} \quad (\text{derate}) \\ u_{proposed} & \text{if } \widetilde{RD} \ge RD_{min} \quad (\text{allow}) \end{cases}$$
evaluated top to bottom (block first).

**Rate limit** (SG-C10-2), applied to allow and derate only:
$$u_t = \min\!\left(\max\!\left(u_{governed,t},\; u_{t-1} - r P_{ref}\right),\; u_{t-1} + r P_{ref}\right)$$

**Operating mode** (ML-RD-02, library D-17): the action outcome above is combined with the scope's FLEXUS governance rules G-1..G-7 by most-restrictive: G-3 or G-7 → block; G-4 → derate and no escalation; G-1, G-2, G-5, G-6 → keep the action outcome, `operating_mode = advisory`, `requires_approval = true` (unless blocked).

### Description
Three outcomes: allow, derate (scale the action by α = 0.5) or block (zero). The old rule compared RD with 0.1 directly, but RD has units (W per °C, W per EUR/MWh, W per %), so the same threshold allowed an action for one stimulus and derated it for another, and changing a price from EUR/kWh to EUR/MWh changed the decision (LO-08). C10 now applies 0.1 to a normalised RD: how much of the asset's rated power a typical (one-sigma) move of the stimulus shifts. RD_min = 0.1 then means "a typical move of the stimulus moves at least 10 % of rated flexibility". The old formula did not say what happens when the deterministic safety check fails with a large RD, nor for negative RD (counter-directional response, ML-RD-01); both now block, as FLEXUS G-7 and G-3 do. The rate limit is 5 % of rated power per step, because "5 % of the previous output" is undefined at zero output. A block is never rate-limited: safety first.

### Python Pseudocode
```python
def c10_govern(u_proposed, rd, rd_status, sigma_x, P_ref, storm_flag, override_flag,
               safety_ok, u_prev=None, rd_min=0.1, alpha_derate=0.5, rate=0.05):
    """rd in W per stimulus unit (rd_stimuli.csv); sigma_x in the same stimulus unit; P_ref in W."""
    if storm_flag or override_flag or not safety_ok or rd is None or rd_status == 'invalidated':
        return 0.0, 'block', None              # never rate-limited
    rd_norm = rd * sigma_x / P_ref
    if rd_norm <= 0:
        return 0.0, 'block', rd_norm           # counter-directional or no response
    if rd_norm >= rd_min:
        outcome, u = 'allow', u_proposed
    else:
        outcome, u = 'derate', alpha_derate * u_proposed
    if u_prev is not None:
        step = rate * P_ref
        u = min(max(u, u_prev - step), u_prev + step)
    return u, outcome, rd_norm

def reconcile(outcome, g_flags):
    """Most-restrictive combination with FLEXUS G-1..G-7 (library D-17)."""
    if g_flags.get('G3') or g_flags.get('G7'):
        return 'block', 'blocked', False
    if g_flags.get('G4') and outcome == 'allow':
        outcome = 'derate'                      # and stop escalating price/signal
    advisory = any(g_flags.get(g) for g in ('G1', 'G2', 'G5', 'G6'))
    mode = 'blocked' if outcome == 'block' else ('advisory' if advisory else 'autonomous')
    return outcome, mode, advisory and outcome != 'block'   # requires_approval
```

## Method
Rule-based gating with a normalised sensitivity threshold. The normalisation is the sigma-normalised derivative of global sensitivity analysis, $S^{\sigma}_x = (\sigma_x / \sigma_y)\,\partial y/\partial x$ (Saltelli et al. 2008, ch. 1; Hamby 1994 reviews scaled sensitivity coefficients), with the output scale $\sigma_y$ replaced by the asset's rated power, so the threshold compares flexibility moved with flexibility available rather than with output variability. Most-restrictive combination with the FLEXUS governance rules G-1..G-7 (FLEXUS SPECS2 §12.1, FX-GOV-01..06; RDObject `governance`, `operating_mode`, `requires_approval` from bundle v2.2).

## RD Role
C10 is RD lifecycle step 6: it consumes RD as a governance primitive (Bible §29) and never optimises it. An RD that C08 invalidated against deterministic bounds is treated as missing and blocks the action (FX-RD-03). The normalised RD is reported with every decision so the decision can be explained from stored records (FX-RD-06).

---

## Validity Limits
- σ_x must be measured in the same scope and units as RD; a σ from a different fragment breaks FX-RD-04.
- With σ_x ≈ 0 (a stimulus that has not moved for 30 days) RD_norm → 0 and actions derate or block; this is intended (no evidence of responsiveness to typical moves), but owners should see the reason code.
- C10 evaluates one action and one RD at a time; it does not check interactions between simultaneous actions (the deterministic `safety_ok` must).
- Thresholds are defaults, to be calibrated (FLEXUS O-09).

## AI Context (Cursor Alignment)
C10 is the safety wrapper around all dispatch. No control signal reaches an actuator without passing through C10. Implements the Response Derivative governance logic on the **normalised** RD: block if RD_norm ≤ 0 (or storm, override, failed safety check, invalidated RD), derate if RD_norm < 0.1, allow if RD_norm ≥ 0.1. Never compare a raw RD with 0.1.
