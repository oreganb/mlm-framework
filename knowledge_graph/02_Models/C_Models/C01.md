# C01 — MILP Flexibility Engine

## Purpose
The core optimisation model. Computes upward and downward flexibility (Flex↑/↓) at each timestep across a rolling horizon H, subject to all physical, comfort, and market constraints. Produces the dispatch schedule for all controllable assets.

## Layer
**RL/Q-Learning** — the deterministic optimiser at the heart of the decision layer. Receives determinized inputs from C03 (Determinization Bridge) and outputs control signals to all assets.

---

## Formula

### LaTeX — Objective Function
$$\min_{\mathbf{x}_t} \sum_{k \in H} \left[ \alpha \cdot C_{energy}(P^{grid}_k, \pi_k) + \beta \cdot C_{comfort}(T^{in}_k) + \gamma \cdot C_{carbon}(P^{grid}_k, EF_k) \right]$$

**Objective terms, with units** *(KG sprint 1, closes SG-C01-1, SG-C01-8; see "Gap closures" below)*, with $\Delta t_h = \Delta t / 3600$:
$$C_{energy,k} = \pi_k \, P^{grid}_k \, \Delta t_h / 1000 \;[\text{EUR}], \qquad C_{carbon,k} = p_{CO_2,k} \, EF_k \, P^{grid}_k \, \Delta t_h / 1000 \;[\text{EUR}]$$
$$C_{comfort,k} = c_{comfort} \, (s^{lo}_k + s^{hi}_k) \, \Delta t_h \;[\text{EUR}], \qquad T^{min}(occ_k) - s^{lo}_k \le T^{in}_k \le T^{max} + s^{hi}_k, \quad s^{lo}_k, s^{hi}_k \ge 0$$

**Net power at PCC:**
$$P^{grid}_k = P^{base}_k - P^{PV}_k - P^{bat,dis}_k + P^{bat,chg}_k - P^{shed}_k - P^{shift}_k + P^{HP}_k + P^{EV}_k$$
*(KG sprint 1, SG-C01-3, SG-C01-6)* $P^{base}_k$ is an input in W from [[L01]]; $P^{EV}_k$ is an exogenous demand in W from [[B03]]; $P^{shed}_k = P^{shift}_k = 0$ in this version (no model defines their bounds or costs). Grid limits: $P^{grid,min}_k = -P^{export,max} \le P^{grid}_k \le P^{grid,max}$ (SG-C01-2).

**Flexibility definitions:**
$$\text{Flex}^{\uparrow}_k = \max \Delta^{\uparrow}_k \quad \text{s.t. } P^{grid}_k - \Delta^{\uparrow}_k \geq P^{grid,min}_k$$
$$\text{Flex}^{\downarrow}_k = \max \Delta^{\downarrow}_k \quad \text{s.t. } P^{grid}_k + \Delta^{\downarrow}_k \leq P^{grid,max}_k$$

**Battery dynamics:**
$$SoC_{k+1} = SoC_k + \frac{\eta_{ch} P^{bat,chg}_k \Delta t}{E_{nom}} - \frac{P^{bat,dis}_k \Delta t}{\eta_{dis} E_{nom}}$$
**Terminal condition** *(owner decision, 2026-10-23)*: the battery ends the horizon at least as charged as it started, in stage 1 and stage 2:
$$SoC_H \ge SoC_0 = SoC_{init}$$

**Thermal comfort (RC model coupling):**
$$T^{in}_{k+1} = a T^{in}_k + b_1 Q^{HVAC}_k + b_2 T^{out}_k + b_3 G_{solar,k}$$
*(KG sprint 1, SG-C01-4, SG-C01-5)* The $b_3$ term takes a heat gain in W, not an irradiance: $G_{solar,k}$ is replaced by $Q^{gain}_k = Q^{solar}_k + Q^{int}_k$ (W, from [[T04]] and [[O01]]/[[L04]], the same gains T01 uses), and $Q^{HVAC}_k = COP_k \cdot P^{HP}_k$ with $0 \le P^{HP}_k \le P^{HP,max}$ (heating only). With $a = e^{-\Delta t/(R_{env} C_{zone})}$, $b_1 = b_3 = R_{env}(1-a)$, $b_2 = 1-a$ this is the exact (zero-order-hold) discretisation of T01's ODE:
$$T^{in}_{k+1} = a\,T^{in}_k + (1-a)\left[T^{out}_k + R_{env}\left(COP_k P^{HP}_k + Q^{gain}_k\right)\right]$$

### Python Pseudocode
```python
def milp_flexibility_engine(horizon_steps, dt_s,
                             weather_det, occupancy_det, price_det,
                             building_params, battery_params, pv_params,
                             weights_alpha, weights_beta, weights_gamma,
                             base_load_det, gains_det, hvac_params, grid_params,
                             ev_det, c_comfort=100.0):
    """
    C01 MILP Flexibility Engine

    KG sprint 1 additions (SG-C01-1..9; see "Gap closures"):
      base_load_det : dict, {P_base[k]} W — from L01 (replaces Q_occ / COP_base)
      gains_det     : dict, {Q_gain[k]} W — Q_solar (T04) + Q_int (O01/L04)
      hvac_params   : dict, {COP[k], P_HP_max} — DS-HVAC or COP curve
      grid_params   : dict, {grid_max, P_export_max} W — from G01
      ev_det        : dict, {P_EV[k]} W — exogenous EV demand from B03
      c_comfort     : EUR per K·h of comfort-band violation  [owner-approved default 100]
      price_det['p_CO2'][k] : EUR per kgCO2 = M09 ETS price (EUR/tCO2) / 1000, via C03 (median)

    Inputs (all determinized — from C03 Determinization Bridge):
      horizon_steps  : int, number of timesteps in horizon H (e.g., 96 for 24h at 15min)
      dt_s           : float, timestep in seconds (900 for 15min)
      weather_det    : dict, {T_out[k], G_POA[k]} — determinized from W-Series (p10 or p50)
      occupancy_det  : dict, {occ_state[k], Q_occ[k]} — from O-Series
      price_det      : dict, {price_DA[k], EF[k]} — from M-Series
      building_params: dict from DS-BUILDING: R_env, C_zone, T_min, T_max
      battery_params : dict from DS-BATTERY: E_nom, eta_ch, eta_dis, SoC_min, SoC_max
      pv_params      : dict: P_PV[k] per timestep (from R01)
      weights_alpha  : float, energy cost weight  [w_alpha, default=0.5]
      weights_beta   : float, comfort weight       [w_beta, default=0.3]
      weights_gamma  : float, carbon weight        [w_gamma, default=0.2]
                       NOTE: alpha + beta + gamma must = 1.0

    Decision variables (per timestep k):
      P_HP[k]       : Heat pump power (W)
      P_EV[k]       : EV charging power (W)
      P_shed[k]     : Load shed (W)
      P_shift[k]    : Load shift (W)
      P_bat_chg[k]  : Battery charge (W)
      P_bat_dis[k]  : Battery discharge (W)
      SoC[k]        : Battery SoC (fraction)
      T_in[k]       : Indoor temperature (°C)
      delta_up[k]   : Upward flexibility (W)
      delta_down[k] : Downward flexibility (W)
    """
    # Build LP/MILP problem
    prob = create_optimisation_problem()

    for k in range(horizon_steps):
        # Net power at PCC
        # KG sprint 1 (SG-C01-3): P_base is an electrical input (W) from L01;
        # occupancy heat Q_occ goes into the thermal gain Q_gain instead.
        P_base = base_load_det['P_base'][k]           # W, from L01
        P_PV = pv_params['P_PV'][k]                   # from R01

        # SG-C01-6: P_EV exogenous (W, from B03); P_shed = P_shift = 0 in this version
        P_grid = (P_base - P_PV
                  - P_bat_dis[k] + P_bat_chg[k]
                  + P_HP[k] + P_EV[k])
        prob.add_constraint(-P_export_max <= P_grid <= grid_max)   # SG-C01-2

        # Objective terms, all in EUR (SG-C01-8): W x h / 1000 = kWh
        C_energy = price_det['price_DA'][k] * P_grid * (dt_s/3600) / 1000
        # SG-C01-1, SG-C01-7: elastic comfort band, occupancy-dependent T_min
        prob.add_constraint(T_in[k] >= T_min_of(occ_state[k]) - s_lo[k])
        prob.add_constraint(T_in[k] <= T_max + s_hi[k])
        C_comfort = c_comfort * (s_lo[k] + s_hi[k]) * (dt_s/3600)   # EUR
        C_carbon = price_det['p_CO2'][k] * price_det['EF'][k] * P_grid * (dt_s/3600) / 1000  # EUR

        prob.minimize(weights_alpha * C_energy      # [w_alpha = 0.5]
                    + weights_beta  * C_comfort     # [w_beta  = 0.3]
                    + weights_gamma * C_carbon)     # [w_gamma = 0.2]

        # Battery dynamics constraint
        prob.add_constraint(SoC[k+1] == SoC[k]
            + eta_ch * P_bat_chg[k] * (dt_s/3600) / E_nom   # [w=eta_ch/E_nom]
            - P_bat_dis[k] * (dt_s/3600) / (eta_dis * E_nom)) # [w=1/(eta_dis*E_nom)]
        if k == horizon_steps - 1:
            prob.add_constraint(SoC[k+1] >= SoC[0])          # terminal: SoC_end >= SoC_start

        # Thermal RC constraint (from T01 parameters)
        a = exp(-dt_s / (R_env * C_zone))                    # [w = RC time constant]
        b1 = R_env * (1 - a)                                  # [w = R_env*(1-a)]
        b2 = (1 - a)                                          # [w = (1-a)]
        b3 = R_env * (1 - a)                                  # [w = R_env*(1-a)]
        Q_HVAC = COP[k] * P_HP[k]                             # SG-C01-4, heating only
        prob.add_constraint(T_in[k+1] == a*T_in[k]
            + b1 * Q_HVAC
            + b2 * T_out[k]
            + b3 * Q_gain[k])                                 # SG-C01-5: W, not irradiance

        # Charge/discharge exclusion with a binary z[k] (AI Context)
        prob.add_constraint(P_bat_chg[k] <= P_chg_max * z[k])
        prob.add_constraint(P_bat_dis[k] <= P_dis_max * (1 - z[k]))

    schedule = prob.solve()                                    # stage 1: dispatch MILP

    # Stage 2 (SG-C01-9): flexibility LP per target step k* and direction,
    # binaries fixed from stage 1 except the battery mode at k*; see "Gap closures".
    flex = {(k, d): flexibility_lp(schedule, k, d)
            for k in range(horizon_steps) for d in ('up', 'down')}
    return schedule, flex
```

| SG-C01-9 Flexibility LP and RD semantics | **Stage 1** (dispatch): the MILP above, with a binary $z_k$ per step for charge/discharge exclusion. **Stage 2** (flexibility at a target step $k^*$, per direction): an LP with every binary fixed at its stage-1 value except $z_{k^*}$, which is set to the direction (discharge allowed for ↑, charge for ↓). Variables at all steps may re-dispatch within every stage-1 constraint; comfort may not be worse than in the schedule ($s^{lo}_k + s^{hi}_k \le s^{lo,*}_k + s^{hi,*}_k$). $\text{Flex}^{\uparrow}_{k^*} = \max \Delta$ s.t. $P^{grid}_{k^*} = P^{grid,*}_{k^*} - \Delta$, $\Delta \ge 0$; $\text{Flex}^{\downarrow}_{k^*} = \max \Delta$ s.t. $P^{grid}_{k^*} = P^{grid,*}_{k^*} + \Delta$. The baseline is the stage-1 schedule $P^{grid,*}$. Fixing the integer variables at their optimal values and reading the duals of the resulting LP is the established way to price a MIP (O'Neill et al. 2005). Each input $x_i$ enters stage 2 as an equality $x_i = \bar{x}_i$; its dual, signed so that $RD_i = \partial \text{Flex}^*/\partial x_i$, is the RD (Boyd & Vandenberghe 2004, §5.6). It is a local, schedule-held sensitivity (`RDObject.estimate.semantics = schedule_held`); at a degenerate vertex the one-sided derivatives differ and C08 must report the dual together with a finite-difference check. | same as D-10h, D-11 |

### Validity limits (KG sprint 1)
- Single thermal zone, heating only, inputs constant within each step (ZOH); Δt ≤ 3600 s.
- RD values are local (valid while the active constraint set does not change) and schedule-held; they are not total derivatives of the full dispatch-then-flexibility pipeline (library D-11 gives a battery example where the two differ in sign).
- The terminal condition SoC_H ≥ SoC_init values stored energy only at its starting level; it does not reward ending higher. With a one-step horizon it forbids any net discharge, so Flex↑ from the battery needs at least one later step in which to recharge.

## Semantic Role & RD Contribution
C01 LP dual variables are the direct source of all RD values. *(Corrected in KG sprint 1, SG-C01-9.)* The RD is the dual of the **stage-2 flexibility LP**, not of the dispatch objective: λ*_i = ∂Flex*/∂x_i (Flex↑ or Flex↓ at step k*, the stage-1 schedule's binaries held), which is what C08 defines (RD = ∂Flex↑/∂x). The dual of the dispatch objective, ∂obj/∂x_i, is a cost sensitivity (EUR per unit of x_i) and is not an RD. C08 reads the stage-2 duals.
