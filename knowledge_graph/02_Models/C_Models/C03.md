# C03 — Determinization Bridge

> **Status: specified** (owner review 2026-10-23; drafted in KG sprint 1). Filled to the ML-KG-04 fields (MLM SPECS2 §12). Closes SG-C03-1 and SG-C03-2 (mlm-library SPEC_GAPS.md; library D-25). Owner decisions are recorded in REVIEW.md.

## Purpose
Converts the probabilistic forecasts of the stochastic series (weather from [[W14]]/[[W02]]/[[W01]] via [[R01]], prices from [[M12]], occupancy from [[O01]], base load from [[L01]]) into the deterministic input trajectories that the [[C01]] MILP requires, in a way that is conservative for the flexibility direction being computed. It also records which determinisation was used, so every RD estimate can state the risk level it was computed at.

## Layer
**RL/Q-Learning** (decision layer, interface to the deterministic optimiser). Deterministic given its inputs: the same distributions and settings always give the same determinised trajectories.

---

## Formula

### LaTeX
For each uncertain input variable $v$ (e.g. $P^{PV}$, $P^{base}$, $T^{out}$, $\pi$, $EF$), step $k$ and flexibility direction $d \in \{\uparrow, \downarrow\}$, with conservative side $\sigma_{v,d} \in \{-1, 0, +1\}$ (defined below):

**Quantile mode** (real-time, horizon ≤ 4 steps):
$$x^{det}_{v,k,d} = F_{v,k}^{-1}(q_{v,d}), \qquad q_{v,d} = \begin{cases} 0.1 & \sigma_{v,d} = -1 \\ 0.5 & \sigma_{v,d} = 0 \\ 0.9 & \sigma_{v,d} = +1 \end{cases}$$

**Ensemble (robust) mode** (near-term, horizon ≤ 12 steps), scenario approach over $S$ ensemble members $\omega_1, \dots, \omega_S$:
$$x^{det,(s)}_{\cdot,k} = \omega_s(k), \qquad \text{Flex}^{robust}_{k,d} = \min_{s = 1..S} \text{Flex}^{(s)}_{k,d}$$
with the reliability guarantee, for i.i.d. members and a continuous distribution of Flex,
$$P\left[\,P\left(\text{Flex}_{k,d} < \text{Flex}^{robust}_{k,d}\right) > \varepsilon\,\right] = (1-\varepsilon)^S$$

**Chance-constraint mode** (day-ahead, horizon ≤ 96 steps), Gaussian marginals:
$$x^{det}_{v,k,d} = \mu_{v,k} + \sigma_{v,d}\, z_{\varepsilon'}\, s_{v,k}, \qquad z_{\varepsilon'} = \Phi^{-1}(1 - \varepsilon'), \qquad \varepsilon' = \begin{cases} \varepsilon & \text{individual (default)} \\ \varepsilon / m & \text{joint, Bonferroni over } m \text{ variables} \end{cases}$$
If only quantiles are supplied: $\mu = q_{0.5}$, $s = (q_{0.9} - q_{0.1}) / (2 \cdot 1.28155)$.

**Conservative side:**
$$\sigma_{v,d} = -\operatorname{sign}\!\left(\frac{\partial \text{Flex}_d}{\partial v}\Big|_{p50}\right)$$
i.e. take the side of the distribution that *reduces* the flexibility offered, using the sign of the RD from [[C08]] evaluated at the median inputs; $\sigma_{v,d} = 0$ (median) for price and emission factor, which enter cost, not feasibility. Fallback table when no RD is available yet: PV $p10$ for ↑ and $p90$ for ↓; base load $p90$ for ↑ and $p10$ for ↓ (the previous C01 table).

**Occupancy (categorical, from O01):** $occ^{det}_k = 0$ (unoccupied) only if $\pi_0(k) \ge 1 - \varepsilon$; otherwise the most probable occupied state $\arg\max_{j \in \{1,2\}} \pi_j(k)$.

### Description
C01 can only optimise one trajectory per input. C03 chooses that trajectory so that the flexibility C01 reports is one the site can actually deliver with high probability. Close to real time, forecasts are sharp and the 10th or 90th percentile is enough (quantile mode). For the next few hours, C03 runs C01 once per ensemble member and keeps the smallest flexibility across members (ensemble, robust mode): with 50 independent members, the chance that this minimum is exceeded by the truth less than 90 % of the time is 0.5 %. Day-ahead, it uses a Gaussian chance constraint, μ ± zσ with z for ε = 0.10. Which side (low or high) is conservative depends on the variable and the direction: more PV helps upward flexibility, more load reduces it. Rather than a fixed table, C03 uses the sign of the variable's own Response Derivative; the old table is the fallback. The previous note named the ensemble mode without defining it (SG-C03-1) and left the distribution and the per-input sign of the chance constraint implicit (SG-C03-2).

### Python Pseudocode
```python
import numpy as np
from scipy.stats import norm

Z = {0.1: norm.ppf(0.9)}                      # 1.28155

def side(var, direction, rd_sign=None):
    """sigma_{v,d}: -1 low tail, +1 high tail, 0 median."""
    if var in ('price', 'EF'):
        return 0
    if rd_sign is not None and rd_sign != 0:
        return -int(np.sign(rd_sign))         # tail that reduces Flex_d
    fallback = {('P_PV', 'up'): -1, ('P_PV', 'down'): +1,
                ('P_base', 'up'): +1, ('P_base', 'down'): -1}
    return fallback.get((var, direction), 0)

def determinise(dist, var, direction, mode, eps=0.10, m_joint=None, rd_sign=None):
    s = side(var, direction, rd_sign)
    if mode == 'quantile':
        q = {-1: 0.1, 0: 0.5, +1: 0.9}[s]
        return dist.quantile(q)               # ensembles: numpy default (Hyndman-Fan type 7)
    if mode == 'chance':
        e = eps / m_joint if m_joint else eps
        mu, sd = dist.mean_sd()               # or from quantiles: (q90 - q10) / (2 * 1.28155)
        return mu + s * norm.ppf(1 - e) * sd
    raise ValueError("ensemble mode determinises scenarios, see robust_flex")

def robust_flex(members, solve_c01_flex, k, direction):
    """Ensemble (robust) mode: one C01 stage-2 solve per member; keep the minimum."""
    flex = [solve_c01_flex(m, k, direction) for m in members]   # members: S x T x vars
    return min(flex), int(np.argmin(flex))

def occupancy_det(pi, eps=0.10):
    return 0 if pi[0] >= 1 - eps else 1 + int(np.argmax(pi[1:]))
```

## Method
- Quantile determinisation: inverse CDF of the predictive distribution (Gneiting & Katzfuss 2014); empirical quantiles of ensembles by the linear-interpolation definition (Hyndman & Fan 1996, type 7, numpy's default).
- Ensemble (robust): the scenario approach (Calafiore & Campi 2006; Campi & Garatti 2008). For a single scalar decision (the deliverable flexibility at one step) and i.i.d. members, the minimum over $S$ members is exceeded with probability below $1-\varepsilon$ only with probability $(1-\varepsilon)^S$; this is the $d = 1$ case of Campi & Garatti's exact bound.
- Chance-constraint: Charnes & Cooper (1959) deterministic equivalent for Gaussian uncertainty; Bonferroni splitting for joint chance constraints is the standard conservative approximation (Nemirovski & Shapiro 2006).

## RD Role
RD lifecycle step 2→4 interface. C03 fixes the operating point at which C01's duals (C08's RD) are evaluated: an RD from a quantile-mode solve is the sensitivity at the conservative quantile, not at the median, and `det_meta` must be carried into the RDObject so consumers know which. In quantile and chance modes the determinised input is a shift of the median ($x^{det} = \mu + \sigma z s$), so $\partial \text{Flex}/\partial \mu = \partial \text{Flex}/\partial x^{det}$ and the RD transfers unchanged. In ensemble mode C03 yields a sample of S RDs (one per member), which C08 uses for the RD's uncertainty (library D-12). C03 also *uses* RD: the conservative side for each variable is the sign of its RD.

---

## Validity Limits
- Chance-constraint mode assumes Gaussian marginals; PV and prices are skewed and bounded, so for them prefer quantile mode with the forecaster's own quantiles (identical to chance mode under a Gaussian, since μ − 1.28155σ is the 10th percentile).
- Individual chance constraints guarantee each variable separately, not jointly, and not the flexibility itself.
- The scenario bound requires i.i.d. members (W14 Monte Carlo draws qualify; a raw NWP ensemble of exchangeable members is treated as i.i.d. by convention) and holds per step and direction.
- The RD-sign side rule assumes monotonicity of Flex in v over the p10–p90 range; if the RD changes sign within it, use ensemble mode.

## AI Context (Cursor Alignment)
C03 is the critical interface between stochastic and deterministic layers. Quantile mode for real-time (<60min), ensemble for near-term (3h), chance-constraint for day-ahead (24h). Never pass a median trajectory to C01 when computing an offered flexibility: use the conservative side. Always pass `det_meta` on, so the RD built from the solve says which quantile or scenario set it was evaluated at.
