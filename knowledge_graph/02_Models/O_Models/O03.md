# O03 — Thermal Comfort Feedback Model

> **Status: specified** (owner review 2026-10-23; drafted in KG sprint 1). Filled to the ML-KG-04 fields (MLM SPECS2 §12). Closes SG-O03-1 and the O03 part of SG-LAYER-1 (mlm-library SPEC_GAPS.md; library D-27). Owner decisions are recorded in REVIEW.md.

## Purpose
Decides when occupant comfort must take priority over flexibility (a comfort override that [[C10]] enforces and [[C01]] respects), says why, and estimates the probability that occupants will override automation themselves. That probability is the human-factor term that lowers the Response Derivative of comfort-sensitive assets (Bible §23; FLEXUS FX-GOV-05).

## Layer
**Stochastic** — the override flag is a deterministic rule on current conditions; the model's stochastic output is the override probability per step and over an activation.

---

## Formula

### LaTeX
**Override flag** (two-sided, occupancy-gated):
$$comfort\_override = manual \;\lor\; \left(occ > 0 \land T_{in} < T_{min,occ}\right) \;\lor\; \left(occ > 0 \land |PMV| > PMV_{thresh}\right)$$
**Override type** (first match in this order):
$$override\_type = \begin{cases} \texttt{manual} & manual \\ \texttt{t\_min} & occ > 0 \land T_{in} < T_{min,occ} \\ \texttt{pmv\_warm} & occ > 0 \land PMV > PMV_{thresh} \\ \texttt{pmv\_cool} & occ > 0 \land PMV < -PMV_{thresh} \\ \texttt{none} & \text{otherwise} \end{cases}$$
**Override probability per step:**
$$p_{ovr}(t) = \mathbf{1}[occ > 0] \cdot \begin{cases} PPD(PMV(t)) / 100 & \text{untrained (upper bound)} \\ \left(1 + e^{-(\beta_0 + \beta_1 |PMV(t)|)}\right)^{-1} & \text{trained (logistic)} \end{cases}$$
**Over an activation of $K$ steps:**
$$p_{ovr}^{act} = 1 - \prod_{k=1}^{K} \left(1 - p_{ovr}(t+k)\right)$$

### Description
A comfort override fires when the occupant presses the manual override, when an occupied home is colder than 19 °C, or when the predicted comfort index is beyond ±1 (too warm or too cool). Overrides only apply when someone is home: an empty house at 16 °C is not a comfort problem (O01, C01 SG-C01-7). The type says which rule fired, so C01 and O15 can respond appropriately (restore heat for `t_min` or `pmv_cool`, stop heating for `pmv_warm`). The previous note wrote a one-sided `PMV > PMV_thresh` in the formula but "|PMV| > 1.0" in the weights, did not list the override types, and, although the model sits in the stochastic layer, gave no probability (SG-O03-1). The probability now comes from Fanger's PPD (the share of people dissatisfied at that PMV) as an untrained upper bound: not every dissatisfied occupant acts. Once override logs exist ([[O15]], [[O11]]), a logistic model of action probability against |PMV| is fitted, as is standard for occupant actions on building controls (Haldi & Robinson 2009).

### Python Pseudocode
```python
import math

def ppd(pmv):
    return 100 - 95 * math.exp(-0.03353 * pmv**4 - 0.2179 * pmv**2)

def o03(PMV, T_in, manual_override, occ_state, pmv_thresh=1.0, T_min_occ=19.0, logit=None):
    occupied = occ_state > 0
    if manual_override:
        kind = 'manual'
    elif occupied and T_in < T_min_occ:
        kind = 't_min'
    elif occupied and PMV > pmv_thresh:
        kind = 'pmv_warm'
    elif occupied and PMV < -pmv_thresh:
        kind = 'pmv_cool'
    else:
        kind = 'none'
    if not occupied:
        p = 0.0
    elif logit is None:
        p = ppd(PMV) / 100                        # untrained upper bound
    else:
        b0, b1 = logit
        p = 1 / (1 + math.exp(-(b0 + b1 * abs(PMV))))
    return {'comfort_override_flag': kind != 'none', 'override_type': kind, 'p_override': p}

def p_override_activation(p_steps):
    q = 1.0
    for p in p_steps:
        q *= 1 - p
    return 1 - q
```

## Method
Threshold rule on PMV ([[T10]], ISO 7730) and indoor temperature. Stochastic part: Fanger's PPD as the probability of a dissatisfied occupant (ISO 7730; Fanger 1970), replaced after training by a logistic regression of override actions on |PMV| (the established model form for occupant interactions with building controls, Haldi & Robinson 2009). Steps are treated as independent in the activation formula.

## RD Role
Stochastic layer, RD lifecycle step 2 (behaviour-conditioned RD). The flag bounds flexibility: while it is set, comfort-sensitive actions are blocked by C10. The probability lowers expected delivered flexibility: for an activation of K steps, $E[\text{delivered}] = (1 - p_{ovr}^{act}) \cdot \text{Flex}$, so the human-factor-adjusted RD is $(1 - p_{ovr}^{act})\,RD$ to first order (Bible §23, "if users are likely to override automation, RD reflects reduced responsiveness"; FX-GOV-05).

---

## Validity Limits
- PMV must be `valid` (T10 limits); otherwise only the manual and t_min rules apply and p_override uses T_in alone after training.
- PPD/100 overstates override probability (most dissatisfied occupants do not act within 15 minutes); it is a conservative placeholder.
- Independence across steps in p_override_act ignores habituation and fatigue; repeated activations need the fatigue model (O-series) before validation.
- Population-level PMV; individual sensitivity differs and is only captured once the logistic is fitted per household.
