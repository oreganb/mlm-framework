# O01 — Occupancy Probability Model

> **Status: specified** (owner review 2026-10-23; drafted in KG sprint 1). Filled to the ML-KG-04 fields (MLM SPECS2 §12). Closes SG-O01-1 (mlm-library SPEC_GAPS.md; library D-35). Owner decisions are recorded in REVIEW.md.

## Purpose
Estimates, every timestep, the probability that a dwelling (or zone) is unoccupied, partly occupied or fully occupied, from motion (PIR), Bluetooth (BLE) and Wi-Fi device counts, and forecasts that probability over the dispatch horizon. Its outputs set internal gains in [[T01]], load scaling in [[L01]], and the comfort band that [[C01]] applies (C01 SG-C01-7).

## Layer
**Stochastic** — returns a probability distribution over states (the filtered and forecast state probabilities) and a confidence, as ML-LIB-02 requires of stochastic models.

---

## Formula

### LaTeX
Hidden state $S_t \in \{0 = \text{unoccupied}, 1 = \text{partial}, 2 = \text{full}\}$, observation $y_t = (\text{PIR}_t, \text{BLE}_t, \text{WiFi}_t)$, hour of day $h_t$.

**Output (unchanged from the previous note):**
$$P_{occ}(t) = \sum_{j \in S} \pi_j(t)\, \mathbf{1}[S_j \neq \text{unoccupied}] = \pi_1(t) + \pi_2(t), \qquad \pi_j(t) = P(S_t = j \mid y_{1:t})$$

**Transition model** (time-inhomogeneous by hour, smoothed):
$$A^{(h)}_{ij} = P(S_t = j \mid S_{t-1} = i, h_t = h) = (1-\lambda)\,\hat{A}^{(h)}_{ij} + \frac{\lambda}{|S|}$$

**Emission model** (per-sensor likelihoods, fused by weighted geometric pooling):
$$b_j(y_t) = \prod_{s \in \mathcal{A}_t} p_s(y_{s,t} \mid S_t = j)^{\tilde{w}_s}, \qquad \tilde{w}_s = \frac{w_s}{\sum_{r \in \mathcal{A}_t} w_r}$$
$$p_{PIR}(y \mid j) = \theta_j^{\,y}(1-\theta_j)^{1-y}, \qquad p_{BLE}(y \mid j) = \text{Poisson}(y;\, \mu^{BLE}_j), \qquad p_{WiFi}(y \mid j) = \text{Poisson}(y;\, \mu^{WiFi}_j)$$
where $\mathcal{A}_t$ is the set of sensors reporting at $t$.

**Filter (forward algorithm, normalised):**
$$\pi(t) \propto b(y_t) \odot \left(\pi(t-1)^{\top} A^{(h_t)}\right), \qquad \sum_j \pi_j(t) = 1$$

**Forecast ($k$ steps ahead):**
$$\pi(t+k \mid t) = \pi(t)^{\top} \prod_{m=1}^{k} A^{(h_{t+m})}, \qquad P_{occ}(t+k \mid t) = \pi_1(t+k \mid t) + \pi_2(t+k \mid t)$$

**State estimate:** $occ\_state(t) = \arg\max_j \pi_j(t)$.

### Description
A three-state hidden Markov model. The hidden state is how occupied the home is; the sensors give noisy evidence about it. Each step, the previous state probabilities are pushed through an hour-dependent transition matrix (people tend to arrive in the evening and leave in the morning) and then reweighted by how likely the current sensor readings are under each state. PIR is a yes/no motion reading per step; BLE and Wi-Fi are device counts modelled as Poisson. The three sensor likelihoods are combined by a weighted geometric mean with the note's weights 0.5/0.3/0.2, renormalised over the sensors that reported. The smoothing λ = 0.05 mixes each transition row with a uniform row so that no transition has zero probability, which lets the filter recover after a missed detection. The previous note named the HMM but defined neither the transition matrix, the emission model, the fusion rule nor what λ did (SG-O01-1).

### Python Pseudocode
```python
import numpy as np
from math import exp, factorial

def o01_filter_step(pi_prev, y, hour, A_by_hour, theta, mu_ble, mu_wifi,
                    w={'pir': 0.5, 'ble': 0.3, 'wifi': 0.2}):
    """One forward step. pi_prev: (3,) probabilities; y: dict pir/ble/wifi, value or None."""
    log_b, w_sum = np.zeros(3), 0.0
    for s, val in y.items():
        if val is None:                      # sensor missing: drop it, renormalise weights
            continue
        if s == 'pir':
            lp = np.log(np.where(val, theta, 1 - theta))
        else:
            mu = mu_ble if s == 'ble' else mu_wifi
            lp = np.array([-m + val * np.log(m) - np.log(factorial(val)) for m in mu])
        log_b += w[s] * lp
        w_sum += w[s]
    b = np.exp(log_b / w_sum) if w_sum > 0 else np.ones(3)
    pred = pi_prev @ A_by_hour[hour]         # A already smoothed: (1-lam)*A_hat + lam/3
    pi = b * pred
    pi /= pi.sum()
    return {'pi': pi, 'P_occ': pi[1] + pi[2], 'occ_state': int(pi.argmax()),
            'o01_confidence': float(pi.max())}

def o01_forecast(pi_t, hours_ahead, A_by_hour):
    out, p = [], pi_t.copy()
    for h in hours_ahead:
        p = p @ A_by_hour[h]
        out.append(p[1] + p[2])
    return out                                # P_occ(t+k | t), k = 1..K
```
Training (offline, monthly): Baum–Welch (EM) on at least four weeks of sensor data per building, one transition matrix per hour of day, emission parameters shared across hours; then apply the λ smoothing.

## Method
Hidden Markov model with forward filtering and Baum–Welch (EM) parameter estimation (Baum et al. 1970; Rabiner 1989). Hour-of-day inhomogeneous transition probabilities follow the Markov-chain presence model of Page et al. (2008), which uses time-dependent transition probabilities derived from a daily occupancy profile. Sensor fusion by weighted logarithmic (geometric) opinion pooling (Genest & Zidek 1986): the weights act as exponents on each sensor's likelihood. Geometric pooling with weights that sum to 1 is chosen over the naive-Bayes product (all exponents 1) because PIR, BLE and Wi-Fi respond to the same people and are not conditionally independent; the product would count the same evidence up to three times and make the filter overconfident.

## RD Role
Stochastic layer, RD lifecycle step 2 (behaviour-conditioned sensitivity). Occupancy is a discrete stimulus, so its effect on flexibility is a difference, not a derivative: C01 evaluated with occ_state = 0 versus 1/2 gives ΔFlex↑ (an empty home can be set back to 16 °C instead of 19 °C, freeing heat-pump headroom). O01 supplies the probabilities that weight it: the occupancy-conditioned expected flexibility is $E[\text{Flex}] = \sum_j \pi_j(t+k \mid t)\,\text{Flex}(j)$, and $\pi$ is passed to [[C03]] for determinisation. RD estimates conditioned on occupancy must carry `o01_confidence`.

---

## Validity Limits
- Device counts are a proxy for people: visitors' phones, phones left at home and always-on devices bias μ; per-building training is required before the outputs are used outside the Lab.
- Poisson emission assumes counts are not overdispersed; if the variance of counts within a state exceeds about twice the mean in training data, switch to a negative-binomial emission (flag for review).
- Trained on four weeks or more; retrain monthly (Validation Checks) or when [[D08]] flags drift in the one-step-ahead log-likelihood.
- Three states only; "partial" means roughly half the household.
- Privacy: only counts enter the model; device identifiers must not leave the building (family rule ML-RDF-19 / PARA//EL L0).

## AI Context (Cursor Alignment)
occ_state drives Q_int calculation in T01. Full occupancy (state=2) uses household_size × q_occ per person. Partial (state=1) uses 50%. Sensor fusion weights must be normalised to sum=1, and renormalised over the sensors that actually reported. Pass the full probability vector π (not only occ_state) to C03 so the determinisation can be risk-aware. Never store BLE/Wi-Fi device identifiers; counts only.
