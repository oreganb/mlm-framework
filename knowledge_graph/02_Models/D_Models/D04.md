# D04 — Sensor Fault Detection Model

> **Status: draft-for-review** (KG sprint 1, 2026-10-23). Filled to the ML-KG-04 fields; not `specified` until the owner has reviewed it (MLM SPECS2 §12). Closes SG-D04-1 and the D04 part of SG-LAYER-1 (mlm-library SPEC_GAPS.md; library D-33). Items marked **OWNER DECISION** are proposals; see REVIEW.md.

## Purpose
Detects faulty sensor readings (stuck, spike, drift, missing) before they corrupt model inputs, says which kind of fault it is, and produces a per-sensor data-quality score. Flagged readings go to [[D06]] for imputation and fault statistics to [[D08]]; the quality score feeds the D-series quality gate that sets model confidence.

## Layer
**AI/ML** — an unsupervised anomaly detector (Isolation Forest) trained per sensor type, followed by a rule-based classifier for the fault type. Training data requirement and confidence output are stated below (ML-LIB-02).

---

## Formula

### LaTeX
**Features** for sensor $i$ at step $t$ (robust-standardised with the sensor's 30-day median and MAD):
$$\mathbf{f}_{i,t} = \left(\, z(x_{i,t}),\;\; z(\Delta x_{i,t}),\;\; z\!\left(\operatorname{sd}_{W}(x_{i})_t\right),\;\; z(r_{i,t})\,\right), \qquad r_{i,t} = x_{i,t} - \operatorname{median}_{k \in N(i)} x_{k,t}$$
$$z(v) = \frac{v - \operatorname{median}(v)}{1.4826\,\operatorname{MAD}(v)}$$
with window $W$ = 16 steps (4 h) and $N(i)$ the same-type sensors in neighbouring buildings (or zones).

**Anomaly score** (Isolation Forest, Liu et al. 2008, 2012), sub-sample size $\psi$:
$$s(\mathbf{f}, \psi) = 2^{-E[h(\mathbf{f})] / c(\psi)}, \qquad c(\psi) = 2H(\psi - 1) - \frac{2(\psi - 1)}{\psi}, \qquad H(i) \approx \ln i + 0.5772156649$$
$$fault\_score_{i,t} = s(\mathbf{f}_{i,t}, \psi), \qquad anomalous_{i,t} = fault\_score_{i,t} > 0.55$$

**Fault type** (first match):
$$fault\_type_{i,t} = \begin{cases} \texttt{missing} & x_{i,t} \text{ absent or non-numeric} \\ \texttt{stuck} & \operatorname{sd}_{W}(x_i)_t < \delta_{res} \;\land\; \operatorname{median}_k \operatorname{sd}_{W}(x_k)_t \ge 5\,\delta_{res} \\ \texttt{spike} & anomalous \land |z(\Delta x_{i,t})| > 5 \land |z(\Delta x_{i,t+1})| > 5,\; \text{opposite signs} \\ \texttt{drift} & |\operatorname{median}_{24h}(r_i)_t| > 3\,\hat\sigma_r \;\text{ for } \ge 24 \text{ h} \\ \texttt{other} & anomalous \\ \texttt{none} & \text{otherwise} \end{cases}$$

**Quality score** (per sensor, trailing 24 h):
$$q_{i} = 1 - \frac{\#\{t : fault\_type_{i,t} \ne \texttt{none}\}}{\#\{t\}}$$

### Description
Each reading is described by four numbers: its own value, its step change, how much it has varied over the last four hours, and how far it is from the median of comparable sensors nearby; all are put on a robust scale so one bad day does not distort them. An Isolation Forest then scores how easy the reading is to isolate from normal data: scores near 1 are anomalies, around 0.5 or below are normal. Readings scoring above 0.55 are anomalous. A short set of rules then names the fault, using the taxonomy of sensor-network fault studies: a sensor that stops changing while its neighbours change is stuck; a jump that immediately reverses is a spike; a persistent offset from the neighbours is drift; a missing value is missing. The previous note's only output, `fault_type`, had no taxonomy; its features were not defined; and "0.55 threshold (5 % contamination)" mixed two different ways of setting an Isolation Forest threshold (SG-D04-1). The 0.55 is applied to the score of Liu et al.; the "5 % contamination" wording is removed, because a contamination rate sets the threshold at a quantile of the training scores instead (TV-D04-5 shows the two differ).

### Python Pseudocode
```python
import numpy as np
from sklearn.ensemble import IsolationForest

def robust_z(v, ref):
    med = np.nanmedian(ref); mad = np.nanmedian(np.abs(ref - med))
    return (v - med) / (1.4826 * mad)

def features(x, neighbours, hist, W=16):
    """hist: the sensor's 30-day history of x, dx, sd, r (robust reference scale)."""
    dx = np.diff(x, prepend=np.nan)
    sd = rolling_std(x, W)
    r = x - np.nanmedian(neighbours, axis=0)
    return np.column_stack([robust_z(x, hist.x), robust_z(dx, hist.dx),
                            robust_z(sd, hist.sd), robust_z(r, hist.r)]), sd, r

def train(F_30days, seed=0):
    return IsolationForest(n_estimators=100, max_samples=256, random_state=seed,
                           n_jobs=1).fit(F_30days)

def d04(x, neighbours, hist, model, delta_res, sigma_r, W=16):
    F, sd, r = features(x, neighbours, hist, W)
    score = -model.score_samples(np.nan_to_num(F))          # Liu et al. score s in (0, 1]
    anomalous = score > 0.55
    nb_sd = np.nanmedian([rolling_std(n, W) for n in neighbours], axis=0)
    zdx = F[:, 1]
    types = []
    for t in range(len(x)):
        if np.isnan(x[t]):
            types.append('missing')
        elif sd[t] < delta_res and nb_sd[t] >= 5 * delta_res:
            types.append('stuck')
        elif anomalous[t] and t + 1 < len(x) and abs(zdx[t]) > 5 and abs(zdx[t + 1]) > 5 \
                and np.sign(zdx[t]) != np.sign(zdx[t + 1]):
            types.append('spike')
        elif persistent(np.abs(rolling_median(r, 96)) > 3 * sigma_r, steps=96):
            types.append('drift')
        else:
            types.append('other' if anomalous[t] else 'none')
    quality = 1 - np.mean([ty != 'none' for ty in types[-96:]])
    return score, anomalous, types, quality
```

## Method
Isolation Forest (Liu et al. 2008; 2012) with the default ensemble of the original paper (100 trees, sub-sample 256), scored on its normalised path-length scale; robust standardisation by median and MAD; a rule-based fault classifier using the fault taxonomy of sensor-network data studies (Ni et al. 2009: stuck-at, spike/outlier, drift/offset among others; Sharma et al. 2010: SHORT, NOISE and CONSTANT faults). The previous note also named an LSTM autoencoder; it is not specified here (**OWNER DECISION**: drop it, or specify it later as an alternative detector behind the same outputs).

## RD Role
AI/ML layer, RD lifecycle step 3 and the confidence side of every RD. D04 does not estimate an RD; faulty inputs lower the quality score that sets the confidence carried by RDs built on them (Bible §25, "D-Series: RD confidence weighting"). An RD whose stimulus or response series contains `stuck` or `drift` readings over its estimation window should not be used for governance until D06 has repaired the data.

---

## Validity Limits
- Needs neighbours for the stuck and drift rules; without neighbours only `missing`, `spike` and `other` can be returned.
- Isolation Forest scores are relative to the training data; after a genuine regime change (new heating system, new occupants) normal readings may score high until the monthly refit.
- One channel at a time; multi-channel physical consistency checks (e.g. supply above return temperature) are D01's job.
- Thresholds are defaults to be calibrated against labelled faults (ODEON Milesight AM319 and Enginko sensors are the expected sources).
